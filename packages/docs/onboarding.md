# 首次配置与加入设备

首次使用有三条不同的路线。先选与你现有设备相符的一条，再完成 Agent 配置。还没安装时，从[快速上手](quick-start.md)开始。

| 你的情况 | 应选的路线 |
| --- | --- |
| 第一次使用，没有自己的网络 | 在第一台电脑的本机网页选择 **新建我的网络**。 |
| 另一台设备上已经有自己的网络 | 在已有管理设备生成加入链接，新设备选择 **加入已有网络**。 |
| 管理浏览器的数据丢失，但还有恢复文件和密码 | 选择 **用恢复文件找回**，恢复原身份。 |

只为一个人建立一张网络。给第二台电脑另建网络不会共享原来的 Bot 和历史。

## 首台电脑的五步流程

在终端运行 `vibeface`，保持 Core 运行，然后在这台电脑的可信浏览器打开 `http://localhost:4790`。

1. **给这台电脑起名**。浏览器名称自动生成，需要时展开 **这个浏览器的名字** 修改。
2. **设置恢复密码**。使用能通过页面强度检查的独立密码。
3. **保存恢复文件**。下载加密文件，确认已经保管，再点 **完成创建**。
4. **让这台电脑运行 Bot**。选择 Agent，完成登录，开启 Bot；也可以稍后配置。
5. **创建第一个 Bot**。填写名称后进入聊天。没有可用 Agent 时，可以先完成创建，随后配置。

恢复文件与密码分开保存。不要发送到 Bot 聊天、工单或代码仓库。它们用于找回管理身份；恢复文件不包含项目、模型登录或完整 Node 数据。

## 配置 Agent 和项目目录

进入这台设备的 **AI** 设置。Codex、Cursor、Claude Code、pi 和 OpenCode 分别配置，不要求全部安装。

1. 选择一个已安装的服务，按页面提示填写程序路径或认证配置。
2. 如果页面提供登录命令，复制到运行 Node 的这台电脑执行。然后点 **检查可用性**。
3. 开启 **运行 Bot**。需要这个服务执行项目任务时，也开启 **执行任务**。
4. 在服务设置里选择各角色的模型。模型列表没有目标名称时，可以手动输入账号支持的名称。
5. 在 **可用文件夹** 中添加实际项目的绝对路径。检查 Bot 使用的是你期望的项目。

Bot 和执行任务是两个角色，可以使用不同服务。没有 Bot 时开启执行任务，系统会让该服务同时运行 Bot，以接收派来的工作。检查显示程序可用不等于真实模型调用成功，最后仍要发送一条测试消息。

默认 Codex、Claude Code 和 OpenCode 使用 Vibeface 的私有认证目录，不直接复用用户终端的登录文件。pi 的认证方式和显式连接外部 Codex App Server 的方式不同，详见[Provider 登录说明](deployment.md#为-node-私有目录登录)。

Bot 的工作目录用于协调会话，项目目录用于项目工作。保留默认 Bot 工作目录即可；自定义时，不要把它设成项目编辑目录。后台服务可能找不到交互式终端里的程序，遇到这种情况，在 **设置 → 高级** 中填写实际程序的绝对路径。

## 加入已有网络

### 添加另一台电脑

1. 在已有管理设备上打开 **添加设备**，选择 **电脑**，复制加入链接。
2. 在新电脑上安装并启动 Vibeface。打开它自己的 `http://localhost:4790`，选择 **加入已有网络**，粘贴链接。
3. 确认新电脑名称，等页面显示 6 位安全码。
4. 回到管理设备，核对名称和安全码完全一致，再点 **一致，允许**。
5. 等待新电脑同步原来的 Bot 和历史，再为它单独配置 Agent、模型登录和项目目录。

也可以在新电脑终端执行：

```sh
vibeface join '<从管理设备复制的完整加入链接>' --name '我的第二台电脑'
```

运行中的 Node 会接收这个加入请求，不必先停止。Node 原本没有运行时，批准完成后再运行 `vibeface`。链接已用过、过期或被拒绝时，从管理设备重新生成。详细重试规则见[添加自己的设备](node.md#添加自己的设备)。

### 添加浏览器或手机

在管理设备的 **添加设备** 中生成链接或二维码，再在自己的浏览器或已安装的手机 App 打开。填入设备名称后，同样核对安全码并批准。只把链接交给自己的设备。

浏览器需要可信 HTTPS 或本机 localhost。手机不能通过自己浏览器的 `localhost` 连接电脑；只有局域网地址时，使用原生 App 的扫码入口，并让手机与电脑处于同一局域网。iOS 需要允许本地网络访问。外网浏览器需要已配置的 HTTPS 公共入口，详见[手机 App 局域网直连](node.md#手机-app-局域网直连)与[公共入口](node.md#配置公共入口)。

网页 App 与原生手机 App 是不同客户端，每个浏览器 profile、站点地址和手机安装都有独立的本地身份。不要把“在另一处打开页面”当成已经获得授权。移动端安装渠道以实际发布情况为准，[下载页](https://www.vibeface.dev/download)不代表已提供 App Store 正式版。

## 恢复管理身份

在连接页面选择 **用恢复文件找回**，选择保存的恢复文件，输入恢复密码，并按页面提示连接原网络的 Node。本机恢复会自动选择本机入口及所需初始化材料。

恢复管理身份不会恢复丢失的项目、Provider 凭证或 Node 数据。仍需有保存历史的 Node 或单独的数据备份。若密码和恢复文件都丢失，又没有其他管理设备，不能依靠网站账号重置。

找回流程涉及更换成员目录时，默认有 48 小时等待期，原有有效管理设备可以确认或否决；不要把提交恢复请求当作已经取得管理权。页面显示的状态和[恢复规则](privacy-security.md#撤销与恢复)为准。

## 确认首次配置完成

- 设备名称正确，已加入预期网络，能看到原来的 Bot 或创建自己的 Bot。
- 恢复文件已经保存，恢复密码另行保管。
- 所选服务启用了 Bot，登录提示已处理，收到过真实的测试回复。
- Bot 的项目与允许目录正确。第二台电脑上的项目、依赖与模型登录已单独准备。

接下来用[日常使用指南](user-guide.md)管理工作。连接失败时先看[排障](troubleshooting.md)，不要通过删除数据目录反复建网来试错。
