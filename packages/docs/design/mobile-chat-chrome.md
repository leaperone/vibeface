# 移动端聊天栏

以下描述源码中的设计意图，不代表 iOS 渲染验收已通过。原生 iOS 聊天记录延伸到顶部导航和底部输入区后方。借鉴 Codync iOS 的轻量导航和悬浮输入区，保留 Vibeface 原有发送、停止、附件与离线状态。Android 保留原有正常布局和外观。

- 顶部保留原生透明导航、系统返回手势和 Bot 信息入口。支持玻璃时，原生导航栏使用跟随应用主题的 `systemUltraThinMaterialLight` 或 `systemUltraThinMaterialDark`，覆盖导航和状态栏区域，避免历史文字直接混入标签。标题不再叠加局部玻璃。
- 附件按钮与输入胶囊并排，最小高度为 52pt。文本自然换行并增长到 160pt 后在框内滚动，44pt 发送与停止按钮贴底对齐。
- 附件入口提供照片图库和文件两种来源。照片图库只选择图片，支持多选；取消选择保留现有草稿与附件，选中的图片沿用附件移除和发送流程。
- 聊天列表铺满页面，输入区绝对定位在底部。完整输入区的实测高度包含附件、离线与草稿提示、底部留白及安全区，作为列表额外 inset。
- 倒置列表保留旧消息端的导航栏留白，最新端留白为 8pt。翻阅旧消息时输入区增长不主动回到底部。
- 键盘展开和交互式收起继续由现有键盘控制器处理。回到底部沿用页面保存的实际 inset 和倒置列表滚动定位。
- 附件按钮和输入胶囊使用 `expo-glass-effect` 的 `regular` 材质并跟随应用明暗主题。读取辅助功能设置前、系统不支持玻璃或启用减少透明度时使用实色背景与导航栏。
- 玻璃和实色背景均通过 `StyleSheet.absoluteFill` 显式铺满原生父视图。材质切换只替换输入框背后的背景，保留输入框和交互子树。草稿提示使用局部实色底。
- 仅调整聊天表现层，不改变消息、授权或同步协议。玻璃组件需要包含 ExpoGlassEffect 的对应原生制品。
- 每轮 Provider、提交模型、推理强度和阶段放入默认收起的“运行信息”。可发送的未确认 Provider 不生成历史卡片，桌面也不常驻同类提示。
- 真正阻塞发送时保留当前原因。离线重连条或带设备设置入口的提示只出现一次，不再同时占用输入框占位和草稿说明；已有历史需要设置时，在输入区给出入口。待回答、结果待确认、失败和重试仍保留在原位置。

验收覆盖长历史、输入增长、附件、发送与停止、键盘开合、回到底部、明暗主题和运行中切换减少透明度。源码检查不能替代 iOS 渲染验收。
