# CLI 作为完整客户端

CLI 与 Web 使用相同的个人网络、Bot、会话和 Core 业务接口。CLI 提供终端交互与机器调用两种呈现方式。身份、输入目标、任务编号和结果核对规则不因入口变化。

## 复用客户端与 Core

`crates/client` 负责认证、签名、附件暂存、持久请求队列和未知结果核对。`apps/cli` 解析命令与参数，显示结果。Core 继续保存共享历史、调度 Bot 并在执行设备登记任务。

CLI 不建立独立的远程执行协议。聊天命令将输入交给已有 Bot，跨设备工作沿用 Bot 向目标 Node 委派的流程。复杂的工作区、设备与文件交付操作使用有类型的业务文档，调用者无需构造 RPC 签名。

## 保留一个持久写入队列

每个客户端身份保留固定的请求队列。输入序号和请求内容在同一次持久化操作里保存。重试引用原操作，不生成新的任务身份。

持续聊天和事件订阅使用不占请求队列锁的只读连接。写入命令短暂持有队列，保存并提交请求，然后释放。并发写入遇到占用时报告忙碌，不另建队列绕过原有顺序。

已接收表示 Core 已保存请求，不表示模型已开始或目标已完成。CLI 显示这些阶段，并保留待核对状态。关闭终端只断开客户端，停止回复和停止工作使用明确的业务操作。

## 覆盖 Web 业务功能

功能覆盖以 Web 实际调用的业务操作和共享协议类型为依据，包括身份与恢复、设备配置、Bot、聊天、历史、任务、频道、提问、通知、记忆、定时工作、附件、诊断及实验室文件交付。

命令目录提供每项操作的参数示例和接口映射。覆盖检查对比 Web 调用点、原生客户端操作及 CLI 命令目录，新增功能缺少入口时报告差异。原始 RPC 调用不计作完整业务操作的覆盖。

本机重新加入网络继续使用已有维护命令及其本机权限，不为已移除 Node 增加新的认证模式。恢复文件轮换使用独立的恢复准备流程，保留现有成员，并先保存替换恢复文件。

## 输出与验证

机器调用的标准输出只包含 JSON 或逐行 JSON。提示、连接信息与诊断写入标准错误。私密设置不进入普通操作结果，一次性决定令牌仅通过明确的私密文件输出操作保存。

验证同时检查命令覆盖和实际行为。受控 Node 与 Provider 夹具验证签名输入、聊天和任务状态、附件字节、重连及原请求核对。命令能够解析不等于业务闭环通过，模拟 Provider 通过也不代表真实模型质量已经验证。

## 设计选择

采用短时写入客户端与独立只读连接，避免为队列锁再引入常驻进程、私有 socket 协议和服务管理。复杂业务参数复用现有类型，减少命令参数与业务规则之间的重复定义。
