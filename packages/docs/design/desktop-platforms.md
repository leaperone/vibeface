# macOS、Windows 桌面与 Windows 本机运行

本次提供 Electron 桌面宿主，复用 React 业务界面，并补齐原生 Windows Rust Core/CLI。用户指定 Grok Bot 为参考；本机 0.79.2 安装包包含 Electron Framework 与 app.asar。Electron 固定为本轮核对过的稳定版本 45.2.3。本轮目标是实现、验证并提交一个 PR，合并与发布另行按授权执行。

## 模块与调用关系

```text
受信任启动器 → 桌面主进程 → 固定路径的 Core 控制接口
业务窗口 → Core 托管的 React 页面 → 现有加密客户端与 Core
Core → Provider/SDK → 本机执行
CLI → 本机控制、服务与更新
```

桌面负责窗口、单实例、菜单/托盘、系统交互以及启动、离线和设置状态。Core 继续负责持久化、同步、调度与 Provider。业务窗口开启 sandbox、contextIsolation，关闭 nodeIntegration，不向页面暴露任意进程、文件或管理者能力。

启动器与业务窗口分开。启动器只能通过校验过的窄 IPC 操作本机运行；业务页继续使用 Core 的 CSP、Noise、身份和发送核对流程。保留现有 WSS/LAN 入口及故障切换，不为桌面再代理一套业务网络。

两个独立方案分别评估了 Core 托管页面和内置自定义协议页面加帧代理。选择前者，因为桌面可以独立管理 Core 生命周期，无需改写客户端 origin、cookie 和传输接口。采纳后者关于同源打包、离线启动器和显式运行状态的约束。

本机会话使用 Core 的私有 loopback 来源，默认 `http://127.0.0.1:4791`。当前 `Access` 返回的浏览器入口可能改写到 4790，桌面应以检查结果中的实际 local_listen 与设备身份绑定本机启动信息。单次 token 不进入日志或持久设置。桌面拥有独立的浏览器身份，不复制既有浏览器私钥。

## 运行与更新所有权

主进程将连接状态明确分为已连接的既有实例与自己启动的实例。连接已有服务时不取得启停所有权，不因为端口或数据目录占用而杀进程、清空数据或另起重复实例。

App 自己启动的 Core 使用内置固定路径和显式数据目录，保持私有父进程管道。关闭窗口保留托盘和运行；明确退出时只停止自己的 Core。父进程异常退出也须使自有 Core 正常结束，重启或重新加入网络后仍保留这项生命周期约束。独立服务不启用这个父进程退出条件。

签名 App 中的 CLI、Core、Web 和 SDK 内容来自同一源码的完整运行包，并保持校验清单一致。CLI 更新器管理独立受管安装，不能改写签名 App 内的程序。桌面更新由 App 的安装或更新流程负责，同一安装只有一个更新管理者。

## Windows 范围

Windows 移植包含当前用户隔离的私有 IPC、文件权限、数据锁、进程树、命令/路径、用户级服务以及更新与恢复。正常功能不能用空实现或整块 cfg 排除替代。持久记录中的进程标识不能变成不核实归属就结束新 PID 的操作。

初始桌面验收矩阵为 macOS ARM64 与 Windows x64，后者使用 `x86_64-pc-windows-msvc` 原生目标、`.exe` 程序。独立 Core/CLI 继续使用完整 `.tar.gz` 包格式，Windows 安装和运行不依赖 WSL、Git Bash、管理员权限或开发者模式。已有 Linux 目标保留。

网络或执行结果未知时保留原工作身份并核对，不能重放写操作。现有仅在 Linux 提供的证明生成能力维持其原有平台约束，不以此关闭 Windows 的其他 Core 能力。

## 构建与验收

桌面和 Windows 制品纳入统一产品版本与并行构建，官网独立。数据 epoch、更新协议保持 1，正式版前保持 0.0.1 Nightly。每个平台只等待自身必要输入，完整汇总后由现有唯一发布者交付。

实现按 Windows 运行时、桌面宿主、构建与交付三个边界分工，主 Agent 负责接口、集成和最终验收。开发分支使用已注册的 CI 手动入口运行真实 Windows/MSVC 与 macOS 构建；本机跨目标类型检查不代表 Windows 编译、链接或运行已通过。

验收覆盖当前用户权限与私有通道、已有/自有进程的启停与异常恢复、服务及更新、实际桌面窗口、包内来源与摘要。Provider 使用受控夹具。开发预览与实际发布的签名状态分别记录，不把无签名预览、普通浏览器页面或 pending CI 报告成原生正式交付。


Windows 的维护通道与 Codex App Server 使用不同接口。维护通道是带当前 SID DACL 的命名管道；Codex 使用官方 `unix://PATH`，底层为 Windows AF_UNIX。连接前核对私有父目录和内核报告的对端进程账户。App Server 的路径指针使用 `.endpoint`，不把指针文件当作 socket，也不向上游传入未定义的命名管道 URL。
