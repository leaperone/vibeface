# 原生 GPUI 桌面迁移

本设计是当前 macOS、Windows 和 Linux 桌面的归属说明：原生 GPUI 界面，没有 Electron、preload、Chromium 或桌面 WebView。Web 与 Mobile 继续作为独立客户端存在。下文的功能表是验收范围，不是未完成的迁移步骤。

## 模块归属

桌面进程内运行 GPUI 界面和独立 Rust 个人网络客户端。客户端连接本人网络中的 Node，也能管理可选的本机 Core。纯控制端启动、扫描和选择节点都不初始化或启动 Node。

- `apps/desktop` 拥有原生窗口、输入、时间线、业务页面、通知、激活和本机进程管理。
- `crates/client` 拥有密钥封存、目录验证、加入、恢复、签名、有界连接调度、订阅、业务读取和耐久 outbox。CLI 的对应调用者同时使用这一套，不保留旧实现或别名。
- `crates/protocol` 只承接 Core 已有的纯 wire 类型。存储、调度和 Provider 保留在 Core，不能为了复用 DTO 链入整个 Core。
- `crates/control` 继续负责验证过的本机维护控制；服务与受管更新复用 CLI 的现有能力。
- `crates/secure` 继续拥有签名、Noise、成员治理和恢复规则。原生客户端直接使用 Rust 实现。

后台客户端持有连接、请求表、缓存和待发操作，GPUI 主线程只消费状态与发送用户意图。解密、磁盘、网络和长文本处理不能进入 render。进度可以合并；丢失推送需要标记重读，不能把丢失终态当作同步成功。

## 身份与写入

客户端身份独立于 Node 和 CLI。旧 Electron 页面使用不可导出的 WebCrypto 密钥，原生应用不能读取其 seed。新客户端通过本人管理设备邀请或显式恢复加入网络，不静默复制其他身份、撤销旧成员或删除旧 profile。未确认的旧写入不能改签成新身份重发。

待发操作在发送前持久化原网络、客户端、业务 ID、目标、原始签名字节、附件引用、序号和前置版本。附件文件与 SQLite 不能假定天然原子，需要先持久化内容再提交引用，并在崩溃后回收未引用文件。未知结果先查权威回执。没有可靠的未执行证据时保留未知并停住对应写入序列，允许用户核对；不因本地查不到记录就换 ID 重发。

成员目录在本机验签。连接代数和网络身份共同限制异步结果，旧连接不能覆盖新网络。密钥、恢复 root、capability、cookie 和 Provider 凭证不进入 UI 快照、共享记录或诊断输出。封存密钥使用现有密码学和当前用户私有文件权限；原生安全存储不可用时不降级为明文。

## 本机运行归属

选中的 Node、App 拥有的 Child、用户后台服务分别建模。仅显式启动才能初始化或运行 Node。退出时只关闭 App 自有 Child 的父 stdin，等待优雅退出后再通过持有的进程句柄升级停止。附着已有服务不取得停止权，不按名称或未验证的 PID 杀进程。

后台服务从持久受管目录运行，不依赖 AppImage 挂载或当前 App 的临时目录。把自有 Node 交给服务前，等待原 Child 完全退出。更新保留 bundled、installed、running 版本及摘要冲突、降级拒绝和待恢复语义，不改写签名 App 内的程序。

首个贯通验证从没有 Node 副作用的原生窗口开始，使用受控 Core/Provider 夹具完成加入、真实 Noise 聊天、输入落盘、服务器已接收但回执丢失、重连不重复写入、进度、停止确认与客户端重启恢复。该切片通过后仍须完成整张功能表。

聊天采用稳定 ID 和可变高度可见行列表，文本状态按消息缓存，合并流式更新。性能验证记录同业务数据下的进程总内存、输入响应、帧时间、历史同步与停止延迟，不把没有 Chromium 子进程等同于速度提升。

## 依赖和架构选择

当前候选固定 `gpui-kit =0.9.1`，其依赖为 `gpui-pre =0.3.12`，不可与 crates.io 的 `gpui 0.2.2` 混用。官方发布接口已核对，构建和各平台行为仍须实际验证。项目既有 Rust 最低版本不能未经编译就声称适用于这些图形依赖。

两个独立设计均选择同进程客户端 actor 与可选独立 Core。额外的客户端 sidecar 会增加私有 IPC、版本与进程管理成本，当前没有隔离收益的测量证据；强制启动本机 Core 又破坏纯控制端模式，因此不采用。交叉评审选详细功能/写入契约为基线，并加入上述故障注入切片与 Child 所有权约束。

Core 的数据库锁、串行 RPC、Provider 输出容量、fork 后执行权限以及 Mobile 生命周期问题单独修复和验证，不能把原生界面迁移当作这些问题已解决。
