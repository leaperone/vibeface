# Web 体验规则

页面与数据接口见 [Node 协议参考](../node-protocol.md)。

## 设计原则

每条原则都可以对照截图检验。

1. **每屏一个主操作。** 一屏只有一个实心主按钮，其余用次级或文字按钮。检验方法是数实心按钮的个数。
2. **说明文字不超过 1 行。** 标题下的说明在 375px 宽度下不换行，大约 22 个汉字以内。超出部分放进“详细信息”或帮助链接。
3. **状态用 icon 加 2 到 4 字标签。** 例如“在线”“需要你同意”“已中断”。不写成整句。
4. **术语放进“详细信息”。** 下文的禁用词只能出现在默认折叠的“详细信息”区域里。可以用脚本对 TSX 文案做检查。
5. **反馈出现在操作旁边。** 按钮自身显示进行中，结果用行内提示或 toast 显示。页顶不再堆横幅。只有连接状态是全局的，放在连接胶囊里；唯一的例外是找回等待生效，管理设备的每个页面顶部都显示红色横条，侧栏“任务”换成红色盾牌。
6. **有风险的操作要先说后果，并且能撤销或拒绝。** 加入请求的“允许”旁提供“拒绝”。移除设备、恢复这类不可逆操作要再确认一次，确认文案写出后果。
7. **流程可以中断和回来。** 分步引导显示进度，可以跳过。中途离开后，回到同一路由能接着做。任务页顶部的待处理分区集中列出要人处理的事项。

## 导航

网页和手机 App 使用同一套导航。

- 手机宽度底部有三个标签：消息、任务、设置。任务显示待处理计数；待处理是任务页顶部的分区，没有事项时不显示。网页上设备需要留意时设置标签带标记，手机 App 的设置标签不带标记。宽屏用侧栏：网页把“设置”放在侧栏底部，手机 App 隐藏底部标签栏，设置是侧栏头部的图标按钮。
- 设置是唯一的配置入口。第一行是“我的设备”，进入后可以添加设备，也可以配置每台设备的 AI。下面依次是提醒、外观、安全、高级和问题排查。其他页面不再单独放设置或设备入口。
- 页头右侧只放当前页面的操作。手机首页只保留“新 Bot”。
- 聊天页标题是 Bot 的头像和名字，点击打开这个 Bot 的设置；右上角的齿轮按钮打开同一面板。上下文和会话也从这个面板进入。
- 输入框上方不放常驻控件，只在需要时显示断线提示和待处理提示。输入框不提供发送目标或发送方式的选择。消息默认补充当前工作。消息以“新任务”加空格、冒号或逗号开头，或以 new task 加冒号或逗号开头，或整条消息就是“新任务”或 new task 时，作为新任务发送。工作已结束时，工作页的补充作为新任务发送；工作尚未结束但无法补充，或结果未知时，输入框暂停，结果未知时提示先让 Bot 查结果。从例行任务链接进入时，输入框旁显示“发送给 · 例行任务”（运行时为“补充给”）和“改回主聊天”。网页上，已有的稍后处理输入只在有内容时显示在输入框下方。

## 视觉规范

网页和手机 App 统一使用 [Arc](uiarc-migration.md)。源码固定在 `packages/uiarc/src`，来源与哈希记录在 `packages/uiarc/source.json`。旧 shadcn 和 React Native Reusables 控件不再作为开发入口。

`packages/theme/theme.css`、`native.css` 和 `tokens.ts` 由 `scripts/generate-uiarc-theme.py` 从 Arc foundation 和 motion tokens 生成。Web 使用 `data-theme` 切换明暗主题，Mobile 通过 Uniwind 使用相同的原生颜色。不要在页面或控件里维护另一份色板和尺寸表。

**字体和字重。** 正文、控件和小标题使用 Inter，展示标题使用 Geist，代码和编号使用 Geist Mono。中文使用系统回退字体。只用 400 和 500 字重；通过字号、留白和颜色建立层级。

| 用途 | Arc token | 大小 |
|---|---|---|
| 页面标题 | `text-xl` | 22px |
| 区块标题 | `text-lg` | 18px |
| 正文、消息 | `text-base` | 16px |
| 控件、次要说明 | `text-sm` | 14px |
| 时间和紧凑元数据 | `text-xs` | 12px |

数字列使用 `tabular-nums`。原生控件随系统字号增长，不裁掉文字。字号以 Arc foundation 为准。

**间距和圆角。** 使用 Arc 的 4px 间距网格。控件圆角为 `rounded-control`，18px；面板为 `rounded-panel`，26px；独立内容边界为 `rounded-surface`，34px。默认可点击控件至少 44px 高；原生系统的更大触控要求优先。普通卡片只用边框，阴影保留给浮层。

**颜色。** 页面使用 `background`，内容边界使用 `surface`，浮层使用 `surface-raised`，弱分组和悬停使用 `surface-muted`。正文使用 `foreground`，辅助文字使用 `text-secondary` 和 `text-muted`。选中、进度和强调使用 Arc 的 `accent`，不再保留独立的紫色品牌控件主题。

| 语义 | 用途 | 图标 |
|---|---|---|
| `success` | 在线、已同意、已完成 | `CircleCheck` |
| `warning` | 等待决定、待确认、只读 | `TriangleAlert`、`Hand` |
| `danger` | 失败、移除、拒绝 | `CircleX`、`Ban` |
| `info` | 同步中、切换中、提示 | `Info`、`RefreshCw` |

状态始终有图标或文字，不能只靠颜色。`-subtle` 和 `-border` 由同一 Arc 语义色生成。Bot face 保留身份数据和形状，页面控件统一使用 Arc 色彩，不加身份光晕或装饰渐变。

**组件。** Web 直接使用固定来源的 Arc Button、Input、Textarea、Select、Switch、Checkbox、Drawer 等组件。侧栏、对话、任务和设置使用相应 Arc 区块的布局规则，并接入真实产品数据。不要把库内演示的人物、模型选项或模拟任务复制进产品。

Mobile 的原生移植位于 `apps/mobile/src/components/arc`，`source.json` 标明每个移植对应的 Arc 项目。导航、返回、手势、键盘、安全区域和附件选择保留平台行为。原生移植使用同一套 token，不嵌入 WebView。

前景操作在控件旁显示结果或错误；toast 只用于短暂的后台反馈。待处理事项仍位于任务页顶部。风险确认、恢复和未知写入结果的语义保持不变。

**动效和焦点。** 时长、曲线和按压来自 Arc motion tokens。Web 使用 Arc 自带的键盘焦点规则；原生动画遵守系统减少动态效果设置。列表、抽屉和控件不能通过装饰动效遮住状态。

UI 修改后运行 `pnpm check:ui`。检查会验证来源哈希、生成 token、既有路由和旧 UI 依赖。e2e、截图和界面验收仍按项目的明确授权规则执行。

## 文案规范

**语气。** 用“你”，口语、直接、平静。不用“请”开头的长句，不用“本人”。说明发生了什么和能做什么，不解释原理。

**设备称谓。** 运行中的 Vibeface Node 称为“节点”，电脑或服务器是它的运行载体。手机 App 和浏览器称为“客户端”，设备是两者的统称。手机 App 是轻客户端，可发现并连接局域网节点，不承担中继。保留“添加设备”总入口，分类使用“节点”和“客户端”，客户端说明为“手机 App／浏览器”。管理权限单独标注，仅客户端可成为管理设备，不能按是否启用 AI 判断设备类型。

**长度上限。**

| 位置 | 上限 |
|---|---|
| 页面标题 | 8 字 |
| 卡片标题 | 12 字 |
| 说明 | 1 行，约 22 字 |
| 按钮 | 2 到 4 字，动词开头 |
| 状态标签 | 2 到 4 字 |
| 错误 | 两个短句：发生了什么，下一步做什么 |

**按钮动词。** 每个动作只用一个词，全站一致。

| 动作 | 用词 |
|---|---|
| 新建 | 新 Bot、添加设备 |
| 继续流程 | 下一步、继续 |
| 结束流程 | 完成、开始对话 |
| 设备加入 | 扫码加入、加入；批准时用允许、拒绝 |
| 停止 | 停止 |
| 移除 | 移除设备 |
| 再试 | 重试 |
| 复制 | 复制 |

**排版。** 中文与英文、数字之间加一个空格，如“运行 Codex”“3 个文件”。后端拼好的中文文案不直接显示。标点用全角，省略号用“…”。

**禁用词。** 下列词只能出现在 `Details` 里，或出现在 CLI 和文档中。

Node、Gateway、网关、入口、Relay、中继、同步角色、调度、Peer ID、设备编号、设备密钥、公钥、私钥、Noise、握手、capability、凭证、签名、成员目录、授权记录、个人网络、恢复包、口令、管理 Agent、协调 Agent、原生工作、原生会话、Agent 任务、Provider、SDK、sidecar、待核对、核对、复查、本人、证据、轮次、投递、localhost、JSON、十六进制、epoch、角色、密文、链上、收据、意图、对账、证明、落盘、债权、SHA-256、Groth16、窗口、工作台。安全码、核对码和 Node.js 不算。节点、客户端是正式界面称谓，不在禁用词中。

**旧词。** 下列词已被替换，`Details` 里也不能用：自己启动 → 由 Vibeface 启动，只在网页 → 只在待处理，没有这个 Bot → 找不到这个 Bot，skill → Skill，机器人 → Bot 或外部聊天，管理员 → 管理设备，邀请 → 加入链接。

`apps/app/src/lib/copy.test.ts` 是这两份清单的准绳，检查网页、`packages/client` 和手机 App 文案中的禁用词与旧词，由 `pnpm run test` 执行。
