# Web 体验规则

页面与数据接口见 [Node 协议参考](../node-protocol.md)。

## 设计原则

每条原则都可以对照截图检验。

1. **每屏一个主操作。** 一屏只有一个实心主按钮，其余用次级或文字按钮。检验方法是数实心按钮的个数。
2. **说明文字不超过 1 行。** 标题下的说明在 375px 宽度下不换行，大约 22 个汉字以内。超出部分放进“详细信息”或帮助链接。
3. **状态用 icon 加 2 到 4 字标签。** 例如“在线”“需要你同意”“已中断”。不写成整句。
4. **术语放进“详细信息”。** 下文的禁用词只能出现在默认折叠的“详细信息”区域里。可以用脚本对 TSX 文案做检查。
5. **反馈出现在操作旁边。** 按钮自身显示进行中，结果用行内提示或 toast 显示。页顶不再堆横幅。只有连接状态是全局的，放在连接胶囊里。
6. **有风险的操作要先说后果，并且能撤销或拒绝。** 加入请求的“允许”旁提供“拒绝”。移除设备、恢复这类不可逆操作要再确认一次，确认文案写出后果。
7. **流程可以中断和回来。** 分步引导显示进度，可以跳过。中途离开后，回到同一路由能接着做。每个待处理事项都有自己的 URL。

## 视觉规范

网页和手机 App 共用这套规范。颜色、字号、圆角、阴影和动效曲线的 token 都在 `packages/theme/theme.css`，两端只做平台必需的适配。字体用 Geist，等宽用 Geist Mono。

**间距。** 4px 基准，只用 4、8、12、16、24、32、48。卡片内边距 16，卡片间距 12，区块间距 24，页面左右边距桌面 24、手机 16。

**字号层级。** 只用五级，行高写在括号里。

| 用途 | 字号 | 字重 |
|---|---|---|
| 页面标题 | 20（28） | 600 |
| 区块标题、卡片标题 | 16（24） | 600 |
| 正文、消息 | 15（24） | 400 |
| 次要说明、标签 | 13（20） | 400 或 500 |
| 编号、时间、代码 | 13（20） | 400，等宽，数字用 `tabular-nums` |

标题字距 -0.011em。安全码和核对码用 24px 等宽、字间距 0.1em，分组之间空一格。

**圆角。** 控件 `rounded-lg`，卡片 `rounded-xl`，消息输入框和用户气泡 `rounded-2xl`，气泡带尾角。

**颜色语义。** 四种语义色各有前景、柔和背景、边框三档，明暗两套，用 OKLCH 定义在 `theme.css`。

| 语义 | 用途 | icon |
|---|---|---|
| 成功（绿） | 在线、已同意、已完成 | `CircleCheck` |
| 警告（琥珀） | 需要你同意、待确认、有风险、只读 | `TriangleAlert`、`Hand` |
| 危险（红） | 失败、拒绝后的状态、移除设备、离线超过一天 | `CircleX`、`Ban` |
| 信息（蓝） | 同步中、切换中、提示 | `Info`、`RefreshCw` |

颜色不单独传达含义，必须同时有 icon 和文字。所有普通文本与所在表面的对比度不低于 4.5:1，包括 13px 的次要说明、标签和语义色文字。3:1 只用于 18.66px 粗体或 24px 以上的大字、图形和控件边界。

品牌紫只用于焦点环、未读计数、选中和 logo。

**Bot 色调。** 每个 Bot 的脸色相点亮它对话里的两处：可发送时的发送按钮，开场建议的边框。空对话页的脸后有一圈同色调的静止光晕，约 1.8 倍脸径。数值见 `botTint`，两端相同。

**icon。** 只用 lucide，描边 1.75。行内 16px，导航和状态 20px，空状态 32px。纯 icon 按钮必须有 `aria-label` 和 tooltip。同一概念在全站使用一致的 icon。

**统一组件。**

- `EmptyState`：64px `bg-muted` 圆角底块里放 32px icon，一行标题、最多一行说明、一个主按钮。
- `Skeleton`：与真实布局同形，持续超过 300ms 才显示，避免闪烁。
- `InlineError`：红色 icon 加一句话加一个动作，放在出错控件下方。
- `StatusPill`：icon 加 2 到 4 字。
- 待处理卡片：加入和待确认事项共用一致布局。头部是 icon、类型和设备，正文最多三行，底部是并列的按钮；只有一个按钮时放在标题行右侧。`/inbox` 和对话内共用这个组件。
- `SafetyCode`：分组的大号等宽数字，带“复制”按钮，读屏时逐位朗读。
- `Details`：默认折叠的“详细信息”，下文的禁用词只能出现在它里面；设置页的折叠行 `SettingsDisclosure` 同样默认折叠，视同 `Details`。
- `Toast`：只用于瞬时反馈，在输入框上方（桌面靠右），最多同时两条。要人处理的事进待处理，不用 toast。
- `PageActions`：页面自己的操作放在页头右侧，桌面 icon 加短文字，手机只留 icon。

**暗色。** 默认跟随系统。暗色下卡片用比背景亮一档的表面色，不加阴影，外框用 `--line-strong`，卡内分隔线用 `--border`；只有浮层保留阴影。警告色背景透明度不超过 10%，避免琥珀色整块发亮。

**动效。** 只用于状态变化。只有两档时长：按压、颜色和悬停 150ms，出现、消失、折叠和布局 200ms；曲线统一 `--ease-out`，不回弹。按压缩放 0.97；新消息例外，180ms 上移 5px 淡入；分段控件的选中块滑过去。遵守 `prefers-reduced-motion`。

## 文案规范

**语气。** 用“你”，口语、直接、平静。不用“请”开头的长句，不用“本人”。说明发生了什么和能做什么，不解释原理。

**长度上限。**

| 位置 | 上限 |
|---|---|
| 页面标题 | 8 字 |
| 卡片标题 | 12 字 |
| 说明 | 1 行，约 22 字 |
| 按钮 | 2 到 4 字，动词开头 |
| 状态标签 | 2 到 4 字 |
| 错误 | 两个短句：发生了什么，下一步做什么 |

**按钮动词。** 每个动作只用一个词，全站一致。

| 动作 | 用词 |
|---|---|
| 新建 | 新 Bot、添加设备 |
| 继续流程 | 下一步、继续 |
| 结束流程 | 完成、开始对话 |
| 设备加入 | 扫码加入、加入；批准时用允许、拒绝 |
| 停止 | 停止 |
| 移除 | 移除设备 |
| 再试 | 重试 |
| 复制 | 复制 |

**排版。** 中文与英文、数字之间加一个空格，如“运行 Codex”“3 个文件”。后端拼好的中文文案（如 `chat_controls.rs` 的“原生 Agent请求”）不直接显示。标点用全角，省略号用“…”。

**禁用词。** 下列词只能出现在 `Details` 里，或出现在 CLI 和文档中。

节点、Node、Gateway、网关、入口、Relay、中继、同步角色、调度、Peer ID、设备编号、公钥、私钥、根私钥、Noise、握手、capability、凭证、签名、成员目录、授权记录、个人网络、恢复包、口令、管理 Agent、协调 Agent、原生工作、原生会话、Agent 任务、Provider、SDK、sidecar、待核对、核对（安全码和核对码除外）、复查、本人、证据、轮次、投递、localhost、JSON、十六进制、epoch、角色、工作台。

`crates/node/web/src/lib/copy.test.ts` 检查 JSX 文案中的禁用词，由 `pnpm run test` 执行。
