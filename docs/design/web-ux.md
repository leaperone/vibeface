# Web 体验设计规格

状态为已审核的规格。本文以 `origin/main` 的 `2146505` 为现状，吸收了同一基线上的 Web 架构评审结论。身份流程按 `docs/design/unified-network.md` 第 3 节和 4.5 节的最终形态设计（扫码或打开链接，双方核对安全码，管理员批准）。统一设计合入前，界面用现有后端数据适配，不改协议和后端密码学。

对照截图在 worktree 的 `.artifacts/ux-before/` 下，不提交。截图来自 `2146505` 的 release 构建，两个真实 Node 进程（4950、4951 端口）加受控 SDK 与 App Server 夹具，没有调用真实 Provider。邀请内容、连接链接和二维码在截图里做了模糊处理。下文用 `b01` 这样的编号引用截图。

## 1. 设计原则

每条原则都可以对照截图检验。

1. **每屏一个主操作。** 一屏只有一个实心主按钮，其余用次级或文字按钮。检验方法是数实心按钮的个数。
2. **说明文字不超过 1 行。** 标题下的说明在 375px 宽度下不换行，大约 22 个汉字以内。超出部分放进“详细信息”或帮助链接。
3. **状态用 icon 加 2 到 4 字标签。** 例如“在线”“需要你同意”“已中断”。不写成整句。
4. **术语放进“详细信息”。** 第 6 节的禁用词只能出现在默认折叠的“详细信息”区域里。可以用脚本对 TSX 文案做检查。
5. **反馈出现在操作旁边。** 按钮自身显示进行中，结果用行内提示或 toast 显示。页顶不再堆横幅。只有连接状态是全局的，放在连接胶囊里。
6. **有风险的操作要先说后果，并且能撤销或拒绝。** 每个“同意”旁都有并列的“拒绝”。移除设备、恢复这类不可逆操作要再确认一次，确认文案写出后果。
7. **流程可以中断和回来。** 分步引导显示进度，可以跳过。中途离开后，回到同一路由能接着做。每个待处理事项都有自己的 URL。

## 2. 用户心智模型与术语

用户只需要理解四件事：我的**设备**互相认识；我和**Bot**对话；Bot 在某台设备上**执行任务**；重要动作要**我同意**。加密、签名和网络拓扑都放在这四件事后面，不单独出现。

| 内部概念 | 界面用词 | icon（lucide） | 说明 |
|---|---|---|---|
| 个人网络 | 我的设备 | `MonitorSmartphone` | 不出现“网络”一词，用户看到的就是设备列表 |
| Node（任意） | 设备 | `Server` | 列表里按设备名显示 |
| 当前浏览器所在的本机 Node | 这台电脑 | `Laptop` | 只在本机会话里出现 |
| 浏览器客户端 | 浏览器 | `Monitor` | 窄屏或 UA 判断为手机时用 `Smartphone`，用词“手机” |
| Gateway、`public_url`、入口 | 访问地址 | `Globe` | 入口切换时显示“切换中” |
| Relay、Replica、Scheduler 角色 | 不展示 | 无 | 详细信息里显示为“设备能力” |
| 能运行 Bot 的 Node | 能运行 Bot | `Bot` | 设备卡片上的一个标签 |
| Peer ID、DeviceId、公钥 | 设备编号 | `Hash` | 只在详细信息里出现，默认显示前 10 位 |
| 浏览器设备密钥（CryptoKey） | 设备钥匙 | `KeyRound` | 只在“安全”说明里出现一次：“钥匙只存在这个浏览器里” |
| Noise 握手和端到端加密 | 已加密 | `ShieldCheck` | 连接胶囊的详细信息里显示“端到端加密，已验证设备” |
| 邀请、ticket | 加入链接、二维码 | `Link`、`QrCode` | 原始内容只在“下载文件”里 |
| SAS 短码、配对审核编号 | 安全码 | `ShieldCheck` | 6 位数字，分成两组显示，如 `482 913` |
| 成员目录 | 我的设备 | `MonitorSmartphone` | 同上 |
| `manage=true`、可管理设备 | 管理员 | `Crown` | 只有管理员能添加和移除设备 |
| Revoke | 移除设备 | `Ban` | 确认文案写“这台设备将无法再连接” |
| 恢复包 | 恢复文件 | `FileKey` | |
| 恢复包口令 | 恢复密码 | `Lock` | |
| 根私钥、Genesis、Checkpoint | 不展示 | 无 | |
| 根恢复 | 用恢复文件找回 | `ArchiveRestore` | |
| 机器人 | Bot | `Bot` | 用户创建并命名的对话对象，如“项目 Bot” |
| 管理 Agent、协调 Agent | Bot | `Bot` | 同一个概念，用户不区分“管理”和“协调” |
| Provider（Codex SDK、Cursor SDK） | AI | `Sparkles` | 设备详情里的一组设置，每个服务一行，显示为“Codex”“Cursor” |
| 原生会话、原生工作、Agent 任务、工作 | 任务 | `ListChecks` | 消息流里的卡片。命令行级别的细节在任务详情里 |
| 审批请求 | 需要你同意 | `Hand` | |
| 待核对（pending check） | 待确认 | `CircleQuestionMark` | |
| 通知、待处理汇总 | 待处理 | `Inbox` | 侧栏带数字角标 |
| 自主模式 off/report/continue | 完成后：停下、只汇报、继续做 | `CirclePause`、`ScrollText`、`Workflow` | |
| 项目 roots | 可用文件夹 | `FolderOpen` | |
| 本机自动访问 | 本机免确认打开 | `Laptop` | 只在设备详情里 |
| 写保护、aligning、forked | 只读 | `Lock` | 原因写进详细信息 |
| 同步未完成（incomplete） | 同步中 | `RefreshCw` | |
| 未确认的写入（outbox） | 发送中、未送达 | `Clock`、`CircleAlert` | |

**设备命名。** 设备一律用名字显示。“这台电脑”只用于当前本机会话指向的那台 Node，并在名字后面加灰色小字，不替代名字。名字缺省时按 UA 生成，如“Mac 上的 Chrome”“iPhone 上的 Safari”。Node 缺省名改为建网或加入时填写的名字，现有 `prepare_genesis` 已经接受 `node_name` 参数（`crates/node/src/client.rs:432`），前端补传即可。

## 3. 信息架构与导航

### 3.1 页面清单

采用架构评审推荐的路由，按会话 id 设计数据，暂时保持一个 Bot 一个会话。

| 路由 | 页面 | 层级 | 主操作 |
|---|---|---|---|
| `/` | 手机是消息列表（待处理和各 Bot 的最后一条消息）；宽屏打开最近的对话，侧栏就是列表。`?conversation=` 打开提醒指向的对话 | 一 | 新 Bot |
| `/connect?redirect=` | 连接页：还不是成员的浏览器建网、用加入链接或扫码、连接已保存的设备，或用恢复文件找回；完成后回到 `redirect` | 引导 | 视方式而定 |
| `/join#<invite>` | 新设备加入 | 引导 | 继续 |
| `/inbox` | 待处理：需要你同意、新设备加入、待确认、只读确认 | 一 | 每张卡片自带操作 |
| `/b/:botId` | 与 Bot 对话 | 一 | 发送 |
| `/b/:botId/work/:workId` | 任务详情，桌面为右侧抽屉，手机为全屏 | 二 | 停止任务 |
| `/devices` | 我的设备 | 一 | 添加设备 |
| `/devices/:deviceId` | 设备详情：AI（服务、Bot、执行任务、检查清单、可用文件夹）、访问地址、移除 | 二 | 视状态而定 |
| `/devices/add` | 添加设备：二维码、链接、安全码核对 | 二 | 允许加入 |
| `/settings` | 这个浏览器：提醒、访问地址、恢复文件、外观 | 一 | 无 |

### 3.2 导航

侧栏只有三个一级入口，加底部的设置和连接胶囊，对标 ChatGPT 和 Claude 的对话侧栏、Tailscale 的设备页。

- **待处理**（`Inbox`）。有事项时显示数字角标，没有时角标消失。
- **Bot**。列表直接展开在侧栏，每项是 Bot 名，有待处理时右侧显示琥珀色圆点。列表顶部是“新 Bot”（`Plus`）。
- **设备**（`MonitorSmartphone`）。有设备离线或等待加入时显示圆点。
- 底部是**连接胶囊**和**设置**（`Settings`）。“断开”移到设置页底部，不放在主导航。

连接胶囊格式为“icon + 访问地址名 + 状态”。状态取值为：在线（`Wifi`，绿）、切换中（`ArrowRightLeft`，蓝）、同步中（`RefreshCw`，蓝）、只读（`Lock`，琥珀）、离线（`WifiOff`，灰）。点击后弹出一个小面板，显示当前访问地址、端到端加密已验证、可切换的访问地址列表。入口列表和自动切换在统一设计第三期才有数据，在那之前面板里只有当前地址，状态只有在线、同步中和离线三种。

- 跳过的步骤在 `/inbox` 里留一张“还没配置 Bot”的提示卡，直到完成。

### 4.2 加入新设备

**最终形态（统一设计第二期）。**

```text
管理设备 /devices/add                    新设备 /join#<ticket>
┌──────────────────────────┐            ┌──────────────────────────┐
│ 添加设备                  │            │ 加入「我的设备」          │
│   [ 二维码 ]              │  扫码/链接 │ 这个浏览器叫什么？        │
│   [ 复制链接 ] 10 分钟有效│ ─────────▸ │ [ iPhone 上的 Safari ]   │
│ 等待新设备…               │            │              [ 继续 ]    │
├──────────────────────────┤            ├──────────────────────────┤
│ iPhone 上的 Safari 想加入 │            │ 在管理设备上核对安全码    │
│ 安全码   482 913          │  双方核对  │ 安全码   482 913          │
│ ☐ 设为管理员              │ ◂────────▸ │ 等待批准…                 │
│   [ 拒绝 ] [ 一致，允许 ] │            │                          │
└──────────────────────────┘            └──────────────────────────┘
```

- 新设备打开链接后只做一件事：确认名字。随后显示安全码和“等待批准”。
- 管理设备上，加入请求同时出现在三个地方：添加设备页、`/inbox` 卡片、全局 toast（“iPhone 上的 Safari 想加入”，带“查看”按钮）。侧栏“待处理”角标加一。
- “一致，允许”在安全码显示之后才可用。“设为管理员”默认不选，只对浏览器和手机出现。
- 加入 Node 走同一个界面。新电脑运行 `vibeface` 后打开本机页面，`/connect` 第 1 步选“已有设备？”，粘贴链接，之后与浏览器相同。

**现在的适配（不改后端）。**

| 现状 | 适配 |
|---|---|
| 浏览器邀请是 `#invite=` 链接加原始 JSON（b39） | 显示二维码、“复制链接”和“下载文件”三个按钮。原始 JSON 只在“详细信息”里 |
| 节点邀请是原始 JSON，要求粘贴（b25、b28） | 同样包装成链接（`#invite=`），新电脑本机页面接受粘贴链接或导入文件 |
| 节点邀请要勾选角色（b24） | 去掉勾选，默认授予中继、同步、调度，与新电脑能运行 Bot 一致。接入角色放进详细信息里的“设备能力”，因为它需要公网地址 |
| 审核页显示三到四段 64 位编号（b29、b33、b42、b44） | 两端都显示一个**过渡核对码**，由两端都已拿到的网络编号、邀请方编号和新设备编号在浏览器本地计算，格式见下。完整编号放进详细信息 |
| 新设备要勾选“我已核对”再点“确认加入” | 合并为一个按钮“核对码一致”，对应 `pair_confirm` |
| 管理端没有拒绝 | 加“忽略”。现有后端没有拒绝 RPC，忽略只把这条请求从本机待处理里隐藏，请求到期后失效。最终形态换成真正的“拒绝”（`approve` 带 `reject=true`） |
| 待批准设备只在设置页中部（b32） | 进入 `/inbox` 和 `/devices`，侧栏角标，加 toast。数据仍来自 `pair_requests` |
| 加入后本机页的“连接此节点”是死路（b36） | 未授权的浏览器在已加入的 Node 本机页面上只显示一个主按钮“打开这台电脑”，即现有本机访问。“连接此节点”删除 |
| 在本机地址上生成的手机二维码无法使用（b39） | 当前访问地址是 loopback 时，不生成二维码，卡片改为“手机连不上本机地址”，主按钮“设置访问地址”，跳到设备详情的访问地址项 |

过渡核对码不能等同于最终的 6 位安全码。最终安全码有承诺机制保护，攻击者只有百万分之一的机会。过渡核对码只是现有编号的压缩显示，攻击者可以离线反复生成密钥，去撞出相同的显示值，所以位数要足够长。建议用 12 位数字分三组（约 40 位熵），如 `4821 0937 5512`，两端字号相同，详细信息里保留完整编号。位数已定为 12 位，见第 8 节。

### 4.3 对话

```text
                               帮我检查依赖并修复 ▸
◆ 项目 Bot
  ## 检查结果                ← Markdown 渲染：标题、列表、代码块、表格、链接
  • 构建：通过
  ┌ sh ─────────────── 复制 ┐
  │ npm test                │
  └─────────────────────────┘
  ⟳ 正在读取 package.json…   ← 进展一行，点开展开
┌ ☑ 任务 · Mac mini · 运行中 · 2 分钟 ─── 详情 › ┐
└────────────────────────────────────────────────┘
```

- **Markdown。** 安全渲染，不允许原始 HTML，链接加 `rel="noopener noreferrer"`，代码块带复制按钮。用户自己的消息也渲染，但只渲染行内代码和换行。
- **流式。** 回复逐字出现，光标处显示 `LoaderCircle`。没有文字时只显示一行“思考中”，不额外显示“稍等”“正在回复”两个状态。
- **停止。** 发送按钮在回复时变成停止（`Square`）。停止后保留已经生成的部分，末尾加一行灰色标签“已中断”（`CirclePause`）。前端先把流式片段持久化到会话缓存里，并标记中断状态。统一设计第一期改为后端写入带 `status` 的 bot 消息后，前端直接读取。“取消本轮”同样保留。
- **进展。** “工作进展”“工作进行中”“需要核对”三种折叠标题合并为一行状态，格式为“icon + 当前动作”，点击展开时间线。时间线每项一行，状态用 icon，不出现“你的消息 · 本轮回复已结束”这类标题（b22）。
- **任务卡片。** Bot 派出的任务在消息流里显示为卡片，内容是阶段、目标设备、一句摘要和用时。点击打开 `/b/:botId/work/:workId`。详情里显示实时输出、命令和文件改动，以及“停止任务”。
- **完成后。** 自主模式下拉移到输入框下方的一行小字里：“完成后：只汇报 ▾”。
- **空状态。** 新 Bot 只显示 Bot 名和 2 到 3 个可点击的示例问题，不显示职责说明全文。
- **输入框提示。** 输入框下方的提示每次只显示一条，按“离线 > 只读 > 需要你处理 > 没有可用 Bot”排序。“没有可用 Bot”的提示带一个按钮“去配置”，链接到设备详情（b04）。

- `/inbox` 里显示同一张卡片，并加上 Bot 名和“去对话”链接。

### 4.6 设备与设置

设置页现在把十类内容平铺在一页（b05–b07）。改为按对象拆开，每页只放一个对象的内容。

**我的设备（`/devices`）。** 对标 Tailscale 的机器列表。

```text
我的设备                                     [ 添加设备 ]
┌──────────────────────────────────────────────────────┐
│ Laptop  我的 Mac  这台电脑    ● 在线   Bot 能运行 Bot │
│ Server  Mac mini              ● 在线   Bot           │
│ Smartphone  iPhone 上的 Safari ○ 2 小时前            │
│ Monitor  Mac 上的 Chrome  这个浏览器  Crown 管理员   │
└──────────────────────────────────────────────────────┘
等待加入 (1)
┌ iPhone 上的 Safari · 核对码 4821 0937 5512 ─ [忽略][允许] ┐
```

**设备详情（`/devices/:id`）。** 分组，渐进披露。

1. 头部：名字（可改）、类型 icon、在线状态、管理员标签。
2. **AI**（只对 Node）：一个分组，每个服务一行。
   - 每行是服务图标、名字、状态和用途图标。`Bot` 表示运行 Bot，在各行之间单选，再点一次关闭 Bot；Codex 行另有 `ListChecks` 开关执行任务。没有说明文字。
   - 程序检查：缺什么就在 Bot 那一行给对应的“怎么安装”。
   - 每行的“设置”折叠里放程序、App Server 和环境变量；Bot 所在服务的“设置”里还有模型、Bot 工作文件夹和组件路径。
   - 登录：“首次对话时确认”。
   - 可用文件夹：列表加“添加文件夹”。
   - 保存：用途开关和文件夹立即保存；路径修改后出现“保存”。
   - 现在只能配置当前入口那台 Node。其他设备显示“连到这台设备后才能修改”，并给出它的访问地址。统一设计第二期后，浏览器可以直接以目标 Node 为 `target` 读写设置，这一限制解除。
3. **访问地址**（只对 Node）：显示 `public_url`。为空或是 loopback 时显示一行“手机和其他电脑连不上”，加“怎么设置”。
4. **本机免确认打开**：开关，只在这台电脑的详情里出现。
5. **详细信息**（折叠）：设备编号、公钥、设备能力（中继、同步、接入、调度）、加入时间。
6. 危险区：“移除设备”，二次确认写明“移除后这台设备无法再连接，已有的对话记录会保留”。

**设置（`/settings`）。** 只放和这个浏览器有关的内容。

- 提醒：开关。暂不做 Web Push（协调者已决定，推送要经过浏览器厂商的服务）。
- 访问地址：现有的“连接入口”。统一设计第三期后显示入口列表，可以手动切换。
- 安全与恢复：“下载新的恢复文件”“更换恢复密码”“用恢复文件找回”。这一组只对管理员显示。所有管理浏览器都丢失时，持恢复文件的新浏览器从连接页的“用恢复文件找回”进入同一流程，不需要先成为成员（统一设计 3.5 节）；Node 已建网时也保留这个入口。
- 外观：跟随系统、浅色、深色。
- 底部：“断开这个浏览器”，次级样式。

**用恢复文件找回。** 四步，与统一设计 3.7 节一致：选文件、输密码、选择保留哪些设备、确认。第三步的默认值改为**全部保留**，问题改为“哪台设备丢了？”，由用户勾选要移除的设备。现在 `recovery-controls.tsx:61` 默认去掉旧管理员（入口见 b53），这会把用户正在用的另一台管理设备一起踢掉。设备按名字、类型和最近在线时间列出，不显示编号。

## 5. 视觉规范

沿用现有 shadcn token 和 Geist 字体，只补语义色和规则。

**间距。** 4px 基准，只用 4、8、12、16、24、32、48。卡片内边距 16，卡片间距 12，区块间距 24，页面左右边距桌面 24、手机 16。

**字号层级。** 只用五级，行高写在括号里。

| 用途 | 字号 | 字重 |
|---|---|---|
| 页面标题 | 20（28） | 600 |
| 区块标题、卡片标题 | 16（24） | 600 |
| 正文、消息 | 15（24） | 400 |
| 次要说明、标签 | 13（20） | 400 或 500 |
| 编号、时间、代码 | 13（20） | 400，等宽，数字用 `tabular-nums` |

安全码和核对码用 24px 等宽、字间距 0.1em，分组之间空一格。

**颜色语义。** 四种语义色各有前景、柔和背景、边框三档，明暗两套，用 OKLCH 定义在 `styles.css`。

| 语义 | 用途 | icon |
|---|---|---|
| 成功（绿） | 在线、已同意、已完成 | `CircleCheck` |
| 警告（琥珀） | 需要你同意、待确认、有风险、只读 | `TriangleAlert`、`Hand` |
| 危险（红） | 失败、拒绝后的状态、移除设备、离线超过一天 | `CircleX`、`Ban` |
| 信息（蓝） | 同步中、切换中、提示 | `Info`、`RefreshCw` |

颜色不单独传达含义，必须同时有 icon 和文字。所有普通文本与所在表面的对比度不低于 4.5:1，包括 13px 的次要说明、标签和语义色文字。3:1 只用于 18.66px 粗体或 24px 以上的大字、图形和控件边界。

**icon。** 只用 lucide，描边 1.75。行内 16px，导航和状态 20px，空状态 32px。纯 icon 按钮必须有 `aria-label` 和 tooltip。同一概念在全站只用第 2 节表里的那一个 icon。

**统一组件。**

- `EmptyState`：一个 32px icon、一行标题、最多一行说明、一个主按钮。
- `Skeleton`：与真实布局同形，持续超过 300ms 才显示，避免闪烁。
- `InlineError`：红色 icon 加一句话加一个动作，放在出错控件下方。
- `StatusPill`：icon 加 2 到 4 字。
- `ActionCard`：审批、加入、待确认三种待处理共用。头部是 icon、类型和设备，正文最多三行，底部是并列的按钮。`/inbox` 和对话内共用这个组件。
- `SafetyCode`：分组的大号等宽数字，带“复制”按钮，读屏时逐位朗读。
- `Details`：默认折叠的“详细信息”，第 6 节的禁用词只能出现在它里面。
- `Toast`：右下（桌面）或顶部（手机），最多同时两条。

**暗色。** 默认跟随系统。暗色下卡片用比背景亮一档的表面色，不加阴影。警告色背景透明度不超过 10%，避免琥珀色整块发亮（b20）。

**动效。** 只用于状态变化：抽屉、卡片出现和折叠。时长 150 到 200ms，遵守 `prefers-reduced-motion`。

## 6. 文案规范

**语气。** 用“你”，口语、直接、平静。不用“请”开头的长句，不用“本人”。说明发生了什么和能做什么，不解释原理。

**长度上限。**

| 位置 | 上限 |
|---|---|
| 页面标题 | 8 字 |
| 卡片标题 | 12 字 |
| 说明 | 1 行，约 22 字 |
| 按钮 | 2 到 4 字，动词开头 |
| 状态标签 | 2 到 4 字 |
| 错误 | 两个短句：发生了什么，下一步做什么 |

**按钮动词。** 每个动作只用一个词，全站一致。

| 动作 | 用词 |
|---|---|
| 新建 | 新 Bot、添加设备 |
| 继续流程 | 下一步、继续 |
| 结束流程 | 完成、开始对话 |
| 审批 | 同意一次、拒绝 |
| 设备加入 | 允许、拒绝（过渡期为“忽略”） |
| 停止 | 停止 |
| 移除 | 移除设备 |
| 再试 | 重试 |
| 复制 | 复制 |

**排版。** 中文与英文、数字之间加一个空格，如“运行 Codex”“3 个文件”。后端拼好的中文文案（如 `chat_controls.rs` 的“原生 Agent请求”）不直接显示。标点用全角，省略号用“…”。

**禁用词。** 下列词只能出现在 `Details` 里，或出现在 CLI 和文档中。

节点、Node、Gateway、网关、入口、Relay、中继、同步角色、调度、Peer ID、设备编号、公钥、私钥、根私钥、Noise、握手、capability、凭证、签名、成员目录、授权记录、个人网络、恢复包、口令、管理 Agent、协调 Agent、原生工作、原生会话、Agent 任务、Provider、SDK、sidecar、待核对、核对（安全码和核对码除外）、复查、本人、证据、轮次、投递、localhost、JSON、十六进制、epoch、角色。

落地时加一个文案检查脚本，扫描 `crates/node/web/src` 的 JSX 文本，发现禁用词出现在 `Details` 之外就报错，并接入 `pnpm run test`。
