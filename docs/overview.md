# Vibeface 能帮你做什么

Vibeface 让你在浏览器或手机里向 Bot 提需求，把工作交给自己的电脑，再回到同一段聊天查看阶段、结果和需要你决定的事项。电脑上已安装并登录的 Codex 或 Claude Code 继续执行任务，Vibeface 负责连接设备、协调工作和保存共享历史。

## 在长期聊天里协调工作

你可以为 Bot 设置名称、职责和项目偏好，在同一段聊天中持续交代工作。创建 Bot 只保存设置，不立即调用模型。实际回复和执行仍使用你自己的 Agent 程序、登录和模型服务。

三个名称分别指不同的东西：

| 名称 | 它负责什么 |
| --- | --- |
| Bot | 长期聊天、职责和项目偏好。运行 Bot 的协调 Agent 理解需求、派发工作并汇报结果。 |
| Agent | Codex、Claude Code 等本机程序。它们调用所选模型，读取文件、修改代码和运行工具。 |
| Node | 运行在你电脑或服务器上的 Vibeface 进程。它保存和同步记录，并按配置协调或执行任务。 |

Bot 的协调角色与任务执行角色可以选择不同产品，各自的原生会话和共享 Bot 历史分开保存。具体关系见 [Bot 与任务执行](bot-and-execution.md)。

## 一条需求如何得到结果

以“检查这个项目的失败测试，并说明需要怎样修改”为例。下面解释工作关系，不代表一项已经执行成功的任务。

1. 你在 Bot 聊天交代目标、项目和希望使用的设备。当前负责的 Node 根据共享历史组织这一轮工作。
2. Bot 把工作交给选定电脑。那台电脑需要已经加入同一个人网络，并准备好 Agent、登录和项目目录。
3. 本机 Agent 执行后，任务阶段和持久结果回到原聊天。结果不确定时，先核对原任务，不靠重新派发来代替确认。

关闭网页不会停止 Node 上的工作；电脑休眠、关机、网络或模型服务异常仍会影响推进。任务结束也需要你核对实际产物。

## 共享历史带来什么

同一个人网络的授权 Node 通过签名 DAG 同步 Bot 聊天、设置、任务阶段和结果。DAG 是记录事件及其因果依赖的有向无环图，能让重新连接的设备补齐缺失历史。

共享历史不包含项目文件、依赖、登录或原生 SDK 会话，也不保存完整逐字流式进度。另一台 Node 要先同步历史，再由你切换负责人，才能用共享记录建立自己的 Agent 上下文。历史回放不会启动旧工作。范围和条件见 [历史同步与换设备](history-sync.md)。

## 什么时候值得使用

如果你希望在多个自己的设备间查看同一段 Bot 历史、选择执行电脑，并持续追踪任务，Vibeface 提供这一层协调。只在一台电脑使用原生 Agent 已能完成工作时，直接使用原工具也合适。多聊天渠道接入是另一种需求，可以阅读 [与原生工具及 OpenClaw 的比较](comparison.md)。

设备通过各自密钥证明身份，新设备加入需要管理设备批准。连接验证身份并加密，授权 Node 和所选模型服务仍会处理任务内容。项目目录检查不是操作系统沙箱，详见 [隐私、安全与执行权限](privacy-security.md)。

## 从一台电脑开始

使用支持的 Mac 或 Linux，先准备好已安装并登录的 Agent、自己的模型服务和项目目录。[安装说明](install.md) 给出 Node 的安装与首次启动路径，[Node 使用文档](node.md#配置管理-agent) 说明如何启用 Bot 和任务执行。

当前项目处于 Nightly 阶段。正式版前不保留协议、数据格式和 API 的向后兼容。先用自己的配置完成实际任务，再决定是否用于重要工作。你可以[查看公开源码](https://github.com/leaperone/vibeface)；使用与分发授权以仓库当前的许可声明为准。
