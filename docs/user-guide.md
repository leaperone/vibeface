# 日常使用指南

本指南从已连接、能收到 Bot 回答的工作区开始。尚未配置时，先完成[快速上手](quick-start.md)或[首次配置](onboarding.md)。

## 给 Bot 一个明确的任务

创建或打开一个 Bot，检查名称、说明和项目目录，再在聊天里交代目标、范围及希望使用的电脑。例如：

> 在我的开发电脑上检查这个项目的测试失败原因。先说明原因和建议，不修改文件。

Bot 的协调 Agent 负责理解需求、派发工作和汇报结果，项目任务由所选电脑的 Agent 执行。允许它修改文件前，确认项目路径和权限符合你的意图。

创建 Bot 只保存定义，不立即调用模型。Bot 的说明和项目偏好也不会自动授予目录权限。每台执行电脑都要配置自己的 Agent、模型登录和可用文件夹。

## 看懂聊天里的状态

| 看到的情况 | 接下来做什么 |
| --- | --- |
| 消息排队 | 等待当前回复结束，或取消还未开始的消息。 |
| 正在回复或工作进行中 | 在原聊天查看阶段与结果。关闭网页不会停止 Core 上的任务。 |
| 需要你决定 | 阅读提问，核对操作对象后回答。 |
| 结果待确认、设备连不上 | 先刷新或点 **再查一次**，检查执行电脑与原任务，不重新派发同一写操作。 |
| 报告已完成 | 检查文件、测试输出或实际产物，不能只靠聊天中的成功说明。 |

共享历史记录 Bot 聊天、设置、任务阶段、摘要和结果。完整逐字进度是来源 Node 的临时观察数据，不作为完整共享历史保存。范围见[历史同步与换设备](history-sync.md)。

## 补充、取消与停止

给正在回复的 Bot 追加信息时，是否立即并入取决于 Provider。Codex 可以把补充并入当前回复；其他不支持此能力的服务会排队。以页面显示的送达状态为准。

停止前先区分对象：

- **取消排队**：取消尚未开始处理的消息。
- **停止当前回复**：请求停止 Bot 当前协调轮，不会停止已经派出去的工作。
- **停止工作**：停止选中的执行工作及它派出的子工作。

页面仍显示 **停止中** 或 **还在尝试停止** 时，不能当作已经停止。离线设备的停止请求需要等设备重新连接。停止也不会撤销已经改动的文件，必要时核对项目差异。详细行为见[创建机器人并处理结果](node.md#创建机器人并处理结果)。

## 管理 Bot 的说明、记忆和定时工作

打开 Bot 详情，调整名称、说明和项目偏好。把稳定的职责写进说明，把本次工作的目标写在聊天里。

Bot 详情中的 **持久记忆** 与聊天记录分开，用于之后的工作。核对保存内容，避免把模型密钥或恢复密码写入记忆。定时工作也在 Bot 详情查看与管理；启用前确认负责人电脑能持续运行、Agent 可用，执行结果仍需检查。

删除或修改前先核对作用对象。浏览器关闭、换入口或移除设备，不能代替停止正在执行的工作。

## 换一台电脑继续

先把新电脑[加入同一网络](onboarding.md#加入已有网络)，等待历史同步。准备该电脑上的项目、依赖和 Provider 登录，再打开原 Bot 聊天。

需要转移协调职责时，选择 **交给这台设备处理**。这会用已同步的共享记录建立本机 Agent 上下文，不会搬走另一台机器的原生 SDK 会话，也不会自动复制项目文件。

原设备的工作仍可能在运行。接续之前先核对未完成任务，尤其是结果未知的写操作。历史回放本身不会重跑旧工作。

## 管理设备与访问入口

设备列表中的电脑是运行 Core 的 Node；浏览器与手机是持有独立设备密钥的操作端。**本机管理** 会话与长期加入网络的浏览器身份也不同。

管理设备可以批准加入、重命名和移除设备。移除前确认还有可用的管理设备及恢复材料。至少保留一台管理设备；清除浏览器站点数据或换浏览器 profile 可能需要重新加入。

同一个人网络可以有多个访问入口。入口变化不等于网络变化，保持自己的签名身份，使用已知可信入口。不要因为某个入口离线就重新创建网络。连接与切换规则见[多个访问地址](node.md#多个访问地址)。

## 让 Core 在后台运行

先正常退出前台的 `vibeface`，再安装当前用户的后台服务：

```sh
vibeface service install
vibeface service status
vibeface status
```

日常管理使用：

```sh
vibeface service stop
vibeface service start
vibeface service restart
```

停止 Core 会影响这台设备的正在运行的工作。先处理未完成任务与结果未知的操作，再停止或更新。关闭浏览器本身不会停止 Core。

使用自定义数据目录时，在每个子命令后传入同一个绝对路径，例如：

```sh
vibeface status --data-dir /absolute/path/to/data
```

服务绑定的数据目录不能通过换一个参数随意替代。完整规则见[安装与管理节点](install.md#用-cli-管理后台服务)。

## 更新与备份

GitHub 受管安装使用 `vibeface update`，npm 安装使用 npm 更新。不要在运行中的安装目录直接覆盖一个二进制文件；CLI、Core 和网页资源需要来自同一发行包。

Nightly 不保证协议或数据格式向后兼容。同一网络使用一致版本。更新前核对[发布与更新说明](releasing.md)，保留备份，不把旧数据目录直接交给不同 data epoch 的版本。

恢复文件用于找回管理身份，完整 Node 数据目录备份用于保存本机历史与状态，项目文件还要单独备份。备份 Node 数据前停止该 Node。不要把同一个 Node 数据目录复制到两台机器同时运行；新电脑通过加入流程获得独立身份。

## 连接或执行异常

先保留当前身份与原任务，查看：

```sh
vibeface status
vibeface logs --level warn
```

再到设备的 **AI** 设置检查程序、私有目录登录、模型与可用文件夹。分享日志前检查其中的项目路径和任务内容；不要分享完整数据目录、恢复文件、邀请链接或 Provider 凭证。

更具体的情况见[排障](troubleshooting.md)。文件交付目前是默认关闭的实验能力，不属于首次上手的必要步骤，见[文件交付说明](paid-delivery.md)。
