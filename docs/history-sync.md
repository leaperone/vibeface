# 换设备时，哪些历史会同步

同一个人网络的授权 Node 会同步 Bot 聊天、设置、任务阶段和结果。换电脑继续协调前，要先补齐历史，再由本人切换负责人；工程、登录和原生 Agent 会话需要在新电脑另行准备。

## 签名 DAG 保存什么

DAG 是有向无环图。每个事件带作者签名，并记录它承接的事件和因果依赖。Node 据此补齐历史、验证作者并重建当前视图，不把到达顺序直接当作所有事件的发生顺序。

共享业务历史与本机执行数据各有范围：

| 数据 | 如何保留 |
| --- | --- |
| Bot 名称、说明、项目偏好与聊天 | 进入共享事件历史。 |
| 工作登记、阶段、摘要与持久结果 | 进入共享事件历史，可回到原 Bot 聊天查看。 |
| 消息引用的附件 | 在授权 Node 之间按需补齐，需要仍有可达副本提供正文。 |
| 完整逐字流式进度 | 来源 Node 上的临时观察数据，不作为完整共享历史保存。 |
| 工程文件、依赖和本机环境 | 不随 DAG 自动复制。 |
| 原生 SDK 状态、登录与配置的模型凭证 | 保留在各自设备，不随 Bot 历史迁移。 |

将密钥主动粘进消息或附件，会让它作为正文同步。配置凭证留本机不代表聊天中的秘密会自动清除，详见 [凭证与本机数据](privacy-security.md#凭证与本机数据)。

## 重连如何补齐记录

成员 Node 交换各自已有的记录范围，再请求缺失的签名事件和附件。附件中断后可以从已持久保存的位置续传，完整大小和哈希通过校验后才能使用。

同步依赖可达来源。只有附件哈希而没有任何可达正文副本时，不能凭哈希找回文件。另一台 Node 离线时，当前副本也可能暂时缺少最新阶段或结果。

历史导入与投影重建只还原记录，不启动历史工作。这个规则不等于全网任何操作都严格只执行一次。例如，定时任务的旧负责人长时间失联时，新旧设备仍可能执行同一时刻的工作。需要核对实际副作用时，以原工作和真实产物为准。

## 接着协调需要哪些条件

从另一台电脑查看历史，与让那台电脑负责 Bot，是两个动作。

另一台 Node 先加入同一个人网络并同步所需记录。你再在原聊天选择 **交给这台设备处理**，由该 Node 用共享历史建立自己的协调 Agent 上下文。原生 SDK 进程、缓存、工程和登录不会跟着负责人切换搬过去。

如果旧设备已把任务派到其他电脑，切换负责人后仍要核对那项原工作的状态。缺失历史、执行设备不可达与结果未知有不同原因，不能用新建同名任务替代恢复。操作说明见 [创建机器人并处理结果](node.md#创建机器人并处理结果)，异常情况见 [待核对](node.md#待核对)。

## 同步与备份各自负责什么

同步让在线的授权副本补齐业务记录。备份用来应对副本、磁盘或设备全部丢失。加密恢复包用于找回网络身份与管理授权，不包含聊天正文、工程、Provider 密钥或原生 SDK 会话。

业务历史仍需可达的授权副本或独立数据备份。恢复包的等待与否决条件见 [撤销与恢复](privacy-security.md#撤销与恢复)，完整目录备份与恢复步骤见 [备份与恢复](node.md#备份与恢复)。

不要把运行中的数据目录复制到另一台电脑同时启动；这会复用同一设备身份并可能导致分叉。新设备使用独立身份加入，见 [添加自己的设备](node.md#添加自己的设备) 与 [写入状态排障](troubleshooting.md#写入状态)。
